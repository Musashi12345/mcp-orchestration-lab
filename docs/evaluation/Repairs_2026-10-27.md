# Repairs after the small automatic batch

The user chose to end the batch after its current run, retain all attempts, and use
300,000 observed tokens per run for future four-mode experiments. No new live attempt
is authorized by this repair. The model, 32-call allowance, 90-second model gap,
30-minute run limit and review rules remain unchanged.

`configs/experiments/csv_gap90_300k.yaml` is the owned-stdio CLI configuration;
`configs/experiments/csv_http_gap90_300k.yaml` uses the existing managed HTTP services.
Their settings are identical apart from the MCP connection method. Earlier configs are
retained. Starting services with the HTTP configuration applies the new guard and gap
to the orchestrator without silently changing the old defaults.

## Stopped batch and recovered evidence

`reports/small_input_queue_2026-10-26/` is now `STOPPED_BY_USER`. Seven new attempts
were started; the final Q10 P2 attempt was not started. The current Q10 D2 evaluator
had already exited. The queue helper's command, parent identity and exited evaluator
were checked before stopping only that helper.

`status-before-user-stop.json` preserves the old queue state. `stop-request.json`
records the user's instruction, process identity and current position. `recovery.json`
records recovery of the Q10 P1 and D2 run links from their saved manifests and native
PostgreSQL. Original child manifests were not changed and no model request or retry
was made. PostgreSQL received separate `evaluation_queue_recovery` records.

All **34 model calls** from the seven attempted new runs are included in the updated
collection. Q10 P1 remains unresolved where its original final report could not be
saved; recovering its run ID does not manufacture a grade or a successful answer.
Older pilots and the four selected Q01 attempts remain retained separately.

## Confirmed failures and repairs

| Failure | Evidence and code cause | Repair |
|---|---|---|
| Token allowance exhausted | The old config caps each run at 120,000. Saved Q05 D2/P2 calls reported 148,924/148,234; Q10 D1/P1 reported 122,818/132,210. `Budget.observe` checks received counts after the reply. | New `configs/experiments/csv_gap90_300k.yaml` has the approved 300,000 limit. Earlier configuration files remain unchanged. Budget errors distinguish tokens from elapsed time. |
| Cleaning permission missing | `clean_data` previously allowed an omitted `rules` argument and substituted `Rules()`, which authorizes no operation. The Q05 jobs requested cleaning while their arguments omitted or emptied those permissions. | MCP now requires an explicit rules argument and explains the existing fields. Empty rules return `NEEDS_INPUT` before a worker model request. Unauthorized operations still fail. |
| Case-insensitive label rules | Exact replacements did not provide general matching against supplied labels regardless of case, or rejection of an unexpected label. These behaviors are part of the already-approved Q05 rules. | Generic `label_values` and `normalize_label` support only supplied labels. Ambiguous/blank permitted labels are rejected. Column names and label values are not hardcoded into the production agent. |
| Bad Python JSON | Q10 P1's program record contained an invalid JSON escape. Existing model-format validation caught it; its correction then crossed the token cap. | Python generation/review instructions explain JSON string escaping. Existing strict validation and the existing single correction allowance remain. Invalid replies are retained and their tokens counted; no silent repair is performed. |
| Windows status-file replacement denied | Q10 P1's manifest replacement raised WinError 5. The retained file is not marked read-only. The process holding any temporary lock was not identified. | Mutable JSON snapshots use unique temporary names and bounded local-file retries for Windows sharing/access errors. Permanent failure still raises and retains both old snapshot and pending new evidence. No provider/tool operation is retried by this writer. |
| Missing queue token accounting | The old helper rejected an unfinished manifest before reading its saved run ID. Q10 P1's five model-call records were consequently absent from the collection. | After child exit, the helper reads and accounts for the native run before marking an unfinished manifest `CHECK_ERROR`/`UNRESOLVED_SAVE_ERROR`. The run link is saved even for that error. |

Increasing a token guard does not guarantee that an LLM chooses correct arguments or
valid code. The repair establishes the supported behavior with fixed replies; new live
behavior must be measured in a separately authorized experiment. Observed token limits
remain checked after replies, not a guaranteed hard subscription/spending cap.

## Checks and comparison controls

Tests cover transient and permanent Windows write failures, concurrent snapshot
writers, missing/ambiguous cleaning permissions, label normalization and unexpected
labels, real MCP discovery, malformed JSON followed by the existing correction above
the former token cap, complete token accounting after a final-save failure, and an
independently graded Q05 cleaning/analysis pipeline in all four modes. P1/P2 use the
real Docker runner; the full project check includes temporary native PostgreSQL.

These are deterministic engineering tests, not measured model-generated successes.
The fixed Q05 choices are test fixtures and do not impose a production agent order.
Private expected values are kept in the independent grader, outside model/runner input.

The application source changes for these repairs. Original Q01/Q05/Q10 attempts keep
their original identities and grades. A future comparison of the repaired application
should run every selected mode under the same new source/configuration rather than
mixing original Q01 with newly repaired Q05/Q10. The previous queue's reuse check
deliberately refuses old Q01 baselines with changed source/settings. It is not resumed.

Detailed validation logs, source/configuration hashes and service-readiness results
are retained under `reports/repair_2026-10-27/`.
