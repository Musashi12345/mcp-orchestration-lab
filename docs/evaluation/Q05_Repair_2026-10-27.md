# Q05 rule passing and numeric parsing repair

The user approved keeping Q05 and repairing the missing cleaning arguments and comma
amount handling. The user still supplies only the question and CSV. A model translates
the stated cleaning instructions into the selected tool's arguments.

## What changed

- Shared model instructions explain that prose does not replace required tool arguments.
  No tool choice, column name, agent preference or execution sequence was added there.
- Cleaning's discovered MCP schema already requires `rules`. DAG validation now names
  missing fields and the tool. Python validation also checks known argument objects against
  the discovered schema before accepting a program. It reads syntax and follows local
  values; it never executes generated Python on the host. The existing bounded correction
  step receives these errors, with both rejected and accepted candidates retained.
- Calls whose complete arguments depend on future results still receive the shared
  broker's checks before MCP dispatch. Static checks do not prove a model understood the
  user's meaning, nor do they silently invent missing rules.
- Explicit numeric conversion in Cleaning accepts three-digit comma groups, using a period
  decimal point. It converts `1,799.99` to `1799.99`. Incorrect grouping is rejected with
  the original CSV line number and column. Blank amounts remain blank; identifiers and
  date formats are preserved unless the stated rules authorize changing them.
- The independent Q05 reference has its own grouped-number parser. It does not import
  the agent's implementation. The original question, CSVs and frozen suite manifest are
  unchanged; current source and grader hashes identify the new interpretation.

An empty allowed-changes list still returns `NEEDS_INPUT` before a worker model call.
Operation choice remains with the model and permitted operations remain checked. This
repair does not change the meaning of a completed agent result or remove its explanation.

## Verification

Regression tests deliberately omit rules from the first candidate and require the existing
correction path to fix it before any tool attempt or container starts, in all four modes.
The public small CSV includes a comma amount that becomes a duplicate only after numeric
conversion. Independent grading checks totals, all cleaned rows and the complete change log.
Further tests reject malformed comma numbers and cover IDs, blanks and original data.

`MCP_LAB_INPUT_TEST=1`, together with the existing native PostgreSQL and Docker flags,
enables the local Q05 CSV test in `tests/evaluation/test_cleaning_flow.py`. It creates its
own temporary native database, uses real MCP services and Docker for Python modes, and
supplies fixed model replies. It does not use the user's database or submit model calls.
The local data and detailed test evidence stay in ignored files.

Saved logs and final validation counts are recorded under
[Q05 verification](../../reports/q05_fix_2026-10-27/README.md). Fixed replies verify software
behavior. A fresh live model comparison is a separate experiment; these tests do not
