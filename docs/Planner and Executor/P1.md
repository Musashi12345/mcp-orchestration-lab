# P1: agreed behavior and execution choice

Status, 2026-10-23: implementation started. P1 is not enabled yet. After discussing
Windows options, the user selected a new CSV-only Docker runner. Implementation will
continue after the user's current commit.

## Agreed behavior

- Use the same CSV registration, MCP discovery, Main Task, tool selection, and subtasks
  as DAG planning. Generate Python directly in the last stage, without translating a DAG.
- Accept one program before execution. Limited planning correction follows the D1 rule;
  the main planner does not rewrite code in response to execution results.
- Agents may still make their own model calls through the shared run allowance.
- The program arranges calls, passes results, branches on known outcomes, and can request
  parallel work. Data calculations remain in the same agents as D1/D2.
- Tool requests go through the existing broker and official MCP adapter. Program code
  gets no direct PostgreSQL, credential, arbitrary host-file, or network access.
- Save source, calls, failures, results, files, and final outputs during the run. The
  independent CSV evaluator grades declared final outputs afterward.
- P2 and execution-time code rewriting are outside this P1 step.

## Work completed

`orchestration/runtime.py` now contains the shared execution admission, MCP/worker
contexts, step records, result collection, review tracking, and final records extracted
from the existing DAG executor. `Executor` inherits those methods. Its graph scheduling
and D2 review/replacement logic remain in `executor.py`.

The focused executor, boundary, and previous audit-fix suite passed 33 tests with real
MCP fixtures; Ruff lint/format checks also passed. This is a shared-layer refactor,
not evidence that P1 planning or isolated execution already exists.

## Selected execution approach

Use a new CSV-only Docker runner. The user clarified that this machine is an Azure
Virtual Desktop VM and chose Docker after discussing AppContainer and Windows Sandbox.
The removed pricing runner will not be restored. PostgreSQL stays directly on Windows.

Generated Python will have no direct host-file or network access. It will request checked
tool calls over a narrow channel to the shared runtime. No new runner, Windows feature,
account, or permission grant has been installed during the discussion.
